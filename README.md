# Следене на цените на полети

Всеки ден проверява цените на **Ryanair** и **Wizz Air** по маршрутите, които си описал
във `flights.yaml` – за цяла година напред, в двете посоки – записва ги в SQLite,
търси изгодни комбинации отиване + връщане за 3–4 нощувки (или колкото избереш),
казва дали си струва да купиш сега и праща съобщение в Slack, когато има цена
под целта ти. Резултатите се виждат в сайт в GitHub Pages.

Работи изцяло в GitHub Actions – не трябва да пускаш нищо от компютъра си.

## Как работи

1. **`flights.yaml`** – списъкът с дестинации, желана цена и настройки.
2. **Проверка** (`python -m scanner`, всеки ден в 07:40 българско време):
   - за всеки маршрут и авиокомпания взема най-евтиния полет за всеки ден от
     следващите 12 месеца, в двете посоки (Ryanair: публичния „fare finder“ на
     сайта; Wizz Air: вътрешния API на сайта – същите заявки, които прави браузърът);
   - цените се превръщат в евро по курс на ЕЦБ (летищата извън еврозоната
     отговарят в местна валута);
   - записва ги в `data/flights.db` (SQLite);
   - сглобява комбинациите отиване + връщане по избраните дни и нощувки;
   - ако някоя е под `target_price`, праща Slack съобщение с оценка „купи / изчакай“;
   - записва базата обратно в git и публикува сайта.
3. **Сайтът** (`docs/index.html`) чете `data/summary.json`, който се смята от
   базата при публикуване, и показва за всеки маршрут: най-добрите комбинации,
   препоръка, кога през годината е евтино, история на цената за избраните дати
   и статистика „ако купя сега, ще падне ли още“.

## Настройка

### 1. Маршрути – `flights.yaml`

```yaml
settings:
  home: SOF                     # откъде тръгваш
  airlines: [ryanair, wizzair]  # кои авиокомпании се проверяват по подразбиране
  patterns: [long_weekend, workweek, any]   # за кои дни се търсят комбинации (за Slack)
  nights: [3, 4]                # брой нощувки

routes:
  - to: BCN
    name: Барселона
    target_price: 60            # желана цена отиване + връщане, EUR
  - to: LTN
    name: Лондон (Luton)
    airlines: [wizzair]         # само тази авиокомпания
```

Шаблоните за дни:

| `patterns` | Значение |
|---|---|
| `long_weekend` | тръгване четвъртък или петък, връщане понеделник или вторник |
| `workweek` | тръгване и връщане в делничен ден (понеделник–петък) |
| `any` | без ограничение |

Пълното описание на всички полета е в коментарите на `flights.yaml`. Промениш ли
файла в `main`, проверката тръгва веднага.

### 2. GitHub Pages

Settings → Pages → Build and deployment → Source: **GitHub Actions**. Сайтът ще е на
`https://<потребител>.github.io/<хранилище>/`.

### 3. Slack

Settings → Secrets and variables → Actions → **Secrets**. Или бот, или webhook:

| Secret | Какво е |
|---|---|
| `SLACK_BOT_TOKEN` + `SLACK_CHANNEL_ID` | Bot User OAuth Token (`xoxb-…`) на Slack приложение с права `chat:write`, поканено в канала, и ID-то на канала |
| `SLACK_WEBHOOK_URL` | Incoming webhook (`https://hooks.slack.com/services/…`) |

Без тях всичко работи, само известията се пропускат (пишат се в лога на Actions).

Известие идва, когато някоя от най-евтините комбинации под целта е нова или е
поевтиняла спрямо последното известие за същите дати. `repeat_alerts_daily: true`
праща всеки ден, докато има нещо под целта. `notify_on_errors` праща съобщение,
ако някоя проверка се провали.

### 4. Ако сайтовете блокират GitHub

Actions → **Проверка на API-тата** → Run workflow показва дали Ryanair и Wizz Air
отговарят на заявки от адресите на GitHub. Ако някой от тях блокира, проверката
може да върви от твоя компютър със self-hosted runner:

1. Settings → Actions → Runners → New self-hosted runner, следвай стъпките
   (инсталира се като услуга и работи на заден план).
2. Settings → Secrets and variables → Actions → **Variables** → `RUNNER` = `self-hosted`.

Workflow-ът ще използва твоята машина, ако е включена в момента на проверката.

## Какво показва сайтът

- **Дни / Нощувки** (горе) – сменяш шаблона за дни и броя нощувки (2–7); всичко се
  пресмята наново на място.
- **Най-добрите комбинации** – най-евтините двойки отиване + връщане; за всяка:
  най-ниската цена, виждана досега за същите дати, промяната за седмица и оценка.
  Натискаш ред и виждаш как се е движила цената за тези дати.
- **Оценка** – прости, обясними правила (`scanner/insights.py`, същите са и в сайта):
  под целта ли е, сред най-ниските в историята на маршрута ли е, най-ниска ли е за
  тези дати, расте ли или пада, има ли по-евтини дати, и колко често при такава цена
  и толкова дни преди полета цената е падала още.
- **Кога е евтино да тръгна** – най-евтината комбинация за всеки ден на тръгване
  през следващата година; фонът маркира месеците, които исторически са евтини или скъпи.
- **По месеци** – типичната най-ниска цена по месец от историята срещу най-евтиното сега.
- **Ако купя сега, ще падне ли още?** – от историята: за всеки период „дни преди
  полета“ колко често цената е падала с ≥10 % по-късно, с колко, и колко често е
  поскъпвала накрая. Отделно само за случаите, в които цената вече е била под обичайната.
- **Цени по дати в една посока** – за свободно избиране на дати.

## Старата история

`data/legacy/*.csv` са записите от стария скрипт (Ryanair, 2024–2025). При първата
проверка, ако `data/flights.db` липсва, те се внасят автоматично и веднага дават
статистиките по месеци и „ще падне ли още“. Старият скрипт не пазеше валутата –
тя се разпознава от първата истинска проверка и старите цени се преизчисляват.

## База данни

`data/flights.db` се пази в git и се обновява от всяка проверка. Цените са „на
интервали“: един ред за всяка цена на даден полет, с първата и последната дата на
проверка, на които е видяна – така базата расте само когато цена се промени.
За ръчно разглеждане има изглед с нормални дати и цени:

```sql
SELECT * FROM fares_v WHERE origin = 'SOF' AND destination = 'BCN' ORDER BY flight_date, first_seen;
```

## Локално

```bash
uv sync                                   # зависимости (нужен е uv)
uv run python -m scanner --dry-run        # проверка без запис и без Slack
uv run python -m scanner                  # проверка + data/flights.db + docs/data/summary.json
uv run python -m scanner export           # само summary.json от базата
cd docs && python -m http.server 8000     # http://localhost:8000
uv run pytest                             # тестове
```
